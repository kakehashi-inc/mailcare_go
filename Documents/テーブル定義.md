# テーブル定義 - MailCare

MailCare は 2 種類の SQLite データベースを使います。

| 種類 | ファイル | 内容 |
| --- | --- | --- |
| マスター DB | `data/mailcare.db` | 利用者、トークン、設定、メールアドレス、ジョブ |
| 索引 DB | `data/mails/<address>.sqlite`（メールアドレスごとに 1 ファイル） | 取り込んだメール、纏めグループ、分析報告 |

日時列はすべて UTC で保存します（表示時に利用者のタイムゾーンへ変換します）。既定値を持つ列はありません。すべての列にアプリが値を書き込みます（既定値欄の `-` は既定値なし）。長さを断定できる文字列の列は `VARCHAR(n)` で長さを宣言し、断定できないものは `TEXT` とし、CHECK 制約は使いません（SQLite は宣言長を強制しないため、利用者の入力は入力時に長さを検査し、メール由来の値は全文をそのまま保存します。列挙値はアプリの定数で管理します）。JSON 列は列名を `*_info` とし、型欄に `TEXT (JSON)` と記載して各表の直後にレイアウトを記載します（`mailboxes.detail_info` の 1 列だけで、他のテーブルに JSON 列はありません）。テーブルを追加・変更した場合は本書を更新してください。

マスター DB には上記のほか、マイグレーションツール goose が自身の適用履歴のために作る管理表 `goose_db_version` があります（goose が作成・更新するもので、本書の既定値の規則の対象外です）。

```text
マスター DB                          索引 DB（アドレスごと）
users   tokens   settings            messages 1---0..1 bounces *---0..1 groups 1---* agent_reports
mailboxes 1---* jobs
```

## 1. マスター DB（`data/mailcare.db`）

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| id | INTEGER | NO | AUTOINCREMENT | 主キー |  |
| username | VARCHAR(64) | NO | - | 一意 | ユーザー名（`[A-Za-z0-9_.-]`） |

| email | VARCHAR(254) | NO | - | | 通知用メールアドレス（任意。空なら通知先にならない） |

| id | INTEGER | NO | AUTOINCREMENT | 主キー |  |

| display_name | VARCHAR(128) | NO | - | | 表示名 |

| initial_days | number | 初回受信で遡る日数（既定 90） |

### jobs

バックグラウンド処理（ジョブ）。

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| id | INTEGER | NO | AUTOINCREMENT | 主キー |  |
| kind | VARCHAR(32) | NO | - | | 種別。値: `sync` / `fetch` / `group` / `analyze` / `reindex` / `reclassify` / `notify` / `cleanup` |

| parent_id | INTEGER | YES | - | `jobs.id`（削除時 NULL） | このジョブを投入したジョブ（展開ジョブの子、同期・纏め・再索引・再判定の後続 `analyze`）。直接投入されたジョブは NULL |

| status | VARCHAR(32) | NO | - | | 状態。値: `queued` / `running` / `done` / `error` / `canceled` |
| requested_by | VARCHAR(80) | NO | - | | 投入元（`scheduler` / `cli` / `web:<username>`） |
| progress | TEXT | NO | - | | 進捗テキスト（実行中に随時更新、最新 200 行を改行区切りで保持） |
| result | TEXT | NO | - | | 結果の要約（1 行） |
| error_message | TEXT | NO | - | | 失敗理由（成功時は空） |
| created_at | DATETIME | NO | - | | 投入日時 |
| started_at | DATETIME | YES | - | | 開始日時 |
| finished_at | DATETIME | YES | - | | 終了日時 |

リレーション: `mailbox_id` → `mailboxes.id`（多対 1）。`parent_id` → `jobs.id`（多対 1、自己参照）。索引: `idx_jobs_status_created (status, created_at)`。

## 2. 索引 DB（`data/mails/<address>.sqlite`）

スキーマ版: `PRAGMA user_version = 1`（初版）。JSON 列はありません。

### messages

取り込んだメール（バウンス以外も含む全件）。原文は同じディレクトリの `<message_key>.eml`、デコード済み本文は `<message_key>-1.txt` / `<message_key>-2.txt` / ... と `<message_key>-1.html` / `<message_key>-2.html` / ...（内容のあるセクションごとに 1 ファイル、1 から連番、MIME 順）。

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| id | INTEGER | NO | AUTOINCREMENT | 主キー |  |
| message_key | VARCHAR(28) | NO | - | 一意 | メールキー（`YYYYMMDD-HHMMSS_<12桁hex>`）。ファイル名の基底 |
| folder | TEXT | NO | - | | 取得元フォルダー |
| uidvalidity | INTEGER | NO | - | | 取得時のフォルダーの UIDVALIDITY |
| uid | INTEGER | NO | - | | IMAP UID |
| message_id | TEXT | NO | - | | Message-ID ヘッダー（UIDVALIDITY 変更後の重複判定に使う） |
| subject | TEXT | NO | - | | 件名（MIME デコード済み。検索対象） |
| from_address | TEXT | NO | - | | 差出人アドレス（検索対象） |
| from_name | TEXT | NO | - | | 差出人表示名（検索対象） |
| to_address | TEXT | NO | - | | 宛先アドレス（先頭。検索対象） |
| to_name | TEXT | NO | - | | 宛先表示名（先頭） |
| date | DATETIME | NO | - | | メール日時（Date ヘッダー、無ければ INTERNALDATE、無ければ取得時刻。並び替えに使う） |
| received_at | DATETIME | YES | - | | IMAP INTERNALDATE |
| size | INTEGER | NO | - | | サイズ（バイト） |
| text_count | INTEGER | NO | - | | 内容のある text/plain セクションの数（= `.txt` ファイルの数） |
| html_count | INTEGER | NO | - | | 内容のある text/html セクションの数（= `.html` ファイルの数。骨組みだけの HTML は数えない） |
| body_source | VARCHAR(16) | NO | - | | 判定・抽出に実際に使った本文（`text` = plain の全セクション、`html` = HTML のテキスト。本文が無ければ空。受信直後は優先本文の側、纏めフェーズで確定）。値: `text` / `html` / 空 |
| classified | INTEGER | NO | - | | 纏めフェーズで処理済みなら 1（受信直後は 0）。値: 0 / 1 |
| is_bounce | INTEGER | NO | - | | 対象判定でメールデーモン通知（自動返信を含む）と判定されれば 1。値: 0 / 1 |
| bounce_kind | VARCHAR(32) | NO | - | | 通知の種別（配信不能 / 遅延 / 自動返信 / その他。対象外は空。自動返信と「その他」（失敗の証拠が無いデーモンメール・成功 DSN）はグループに入れず `bounces` 行も持たない）。値: `failed` / `delayed` / `auto_reply` / `other` / 空 |
| rule | VARCHAR(64) | NO | - | | 対象判定で一致したルール名（`dsn_report` / `daemon_sender` / `subject_pattern` / `auto_reply` / `daemon_display_name` / `body_pattern`。対象外メールは空） |
| fetched_at | DATETIME | NO | - | | 取り込み日時 |

制約: `UNIQUE(folder, uidvalidity, uid)`。索引: `idx_messages_date (date)`、`idx_messages_message_id (message_id)`、`idx_messages_bounce (is_bounce, date)`、`idx_messages_classified (classified)`。
リレーション: `bounces.id` から参照される（1 対 0..1）。

### bounces

バウンスメールから抽出した詳細（`bounce_kind` が `failed` / `delayed` のメールに 1 行。自動返信、`other`（失敗の証拠が無いデーモンメール。成功 DSN を含む）と対象外メールには無い）。

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| id | INTEGER | NO | - | 主キー、`messages.id`（メール削除時にカスケード削除） | 元のメール |
| group_key | VARCHAR(16) | NO | - | | 所属する纏めグループ（`groups.group_key`。未所属は空） |
| recipient | TEXT | NO | - | | 配信できなかった宛先アドレス（グループの宛先数の集計に使う） |
| recipient_domain | TEXT | NO | - | | 宛先ドメイン |
| action | VARCHAR(32) | NO | - | | DSN の Action。値: `failed` / `delayed` / `delivered` / `relayed` / `expanded` / 空 |
| status_code | VARCHAR(11) | NO | - | | 拡張状態コード（例 `5.1.1`） |
| smtp_code | VARCHAR(3) | NO | - | | SMTP 応答コード（例 `550`。通知に実値が無ければ空） |
| diagnostic | TEXT | NO | - | | 診断文（Diagnostic-Code または本文から抽出） |
| diagnostic_template | TEXT | NO | - | | 診断テンプレート（揺れを除いた正規化文字列） |
| remote_mta | TEXT | NO | - | | 相手側 MTA のホスト名（グループの MTA 一覧に使う） |
| remote_ip | VARCHAR(45) | NO | - | | 相手側 MTA の IP アドレス（グループの IP 数の集計に使う） |
| reporting_mta | TEXT | NO | - | | 通知を作成した MTA（当方側） |
| original_message_id | TEXT | NO | - | | 元メールの Message-ID |
| original_subject | TEXT | NO | - | | 元メールの件名 |
| original_from | TEXT | NO | - | | 元メールの差出人 |
| original_date | DATETIME | YES | - | | 元メールの日時 |

索引: `idx_bounces_group (group_key)`。
リレーション: `id` → `messages.id`（1 対 1）。`group_key` → `groups.group_key`（多対 1、外部キー制約なし）。

### groups

バウンスを対応基準単位で束ねた纏めグループ。

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |

| recipient_domain | TEXT | NO | - | | 代表の宛先ドメイン（検索対象） |

| diagnostic_template | TEXT | NO | - | | 代表の診断テンプレート（検索対象） |
| responsible | VARCHAR(32) | NO | - | | 対応者区分（カテゴリ由来。解析報告の META が確定値を返せば上書き。絞り込みに使う）。値: `sender` / `recipient` / `domain` / `unknown` / 空 |
| state | VARCHAR(32) | NO | - | | 対応状態（絞り込みに使う）。値: `open` / `resolved` / `ignored` |
| state_updated_at | DATETIME | YES | - | | 状態の変更日時 |
| needs_analysis | INTEGER | NO | - | | 解析が必要（新規、メールが増えた、前回の解析が失敗）なら 1。解析完了で 0。対象外グループ（`actionable` = 0）は作成時も件数増加時も 0。値: 0 / 1 |

| recipient_count | INTEGER | NO | - | | 宛先アドレスの種類数 |
| remote_ip_count | INTEGER | NO | - | | 相手側 IP の種類数 |
| first_seen | DATETIME | YES | - | | 最古のメール日時 |
| last_seen | DATETIME | YES | - | | 最新のメール日時（並び替えに使う） |
| created_at | DATETIME | NO | - | | 作成日時 |
| updated_at | DATETIME | NO | - | | 更新日時 |

リレーション: `bounces.group_key` から参照される（1 対多）。`agent_reports.group_key` から参照される（1 対多）。

### agent_reports

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |

| id | INTEGER | NO | AUTOINCREMENT | 主キー |  |

| summary | TEXT | NO | - | | 要約（META の summary、無ければ報告の冒頭） |
| report_markdown | TEXT | NO | - | | 報告本文（Markdown） |
