# テーブル定義 - MailCare

MailCare は 2 種類の SQLite データベースを使います。

| 種類 | ファイル | 内容 |
| --- | --- | --- |
| マスター DB | `data/mailcare.db` | 利用者、トークン、設定、メールアドレス、ジョブ、DNS 検証結果、自分たちの送信元の取得結果 |
| 索引 DB | `data/mails/<address>.sqlite`（メールアドレスごとに 1 ファイル） | 取り込んだメール、纏めグループ、分析報告 |

日時列はすべて UTC で保存します。既定値を持つ列はありません（既定値欄の `-` は既定値なし）。長さを断定できる文字列の列は `VARCHAR(n)` で長さを宣言し、断定できないものは `TEXT` とし、CHECK 制約は使いません（列挙値は各列の「値」に記載します）。JSON 列は列名を `*_info` とし、型欄に `TEXT (JSON)` と記載して各表の直後にレイアウトを記載します（`mailboxes.detail_info` の 1 列だけで、他のテーブルに JSON 列はありません）。テーブルを追加・変更した場合は本書を更新してください。値の扱い（いつ・どう書き込むか、画面や処理での使われ方）は [システム仕様.md](システム仕様.md) に記載します。

どちらの DB もマイグレーションツール goose で管理します（マスター DB は `embedded/migrations/master/`、索引 DB は `embedded/migrations/index/`）。各 DB には goose が自身の適用履歴のために作る管理表 `goose_db_version` があります（goose が作成・更新するもので、本書の既定値の規則の対象外です）。索引 DB の表に後から NOT NULL の列を足すマイグレーションでは、既存の行のために既定値を持たせることがあります（SQLite の制約による例外。その列は本書の既定値欄に記載します）。

```text
マスター DB                          索引 DB（アドレスごと）
users   tokens   settings            messages 1---0..1 bounces *---0..1 groups 1---* agent_reports 1---* agent_report_patterns
mailboxes 1---* jobs   dns_checks own_source_lookups                    groups 1---* group_state_changes 1---* group_state_change_patterns
```

### dns_checks

名前解決の失敗の通知について、名前を実際に引いて確かめた結果（[メール判定仕様](メール判定仕様.md) 4.4）。メールアドレスをまたいで共有し、再索引でも失われないようマスター DB に置く。保留（確かめられなかった）結果は保存しない。DNS 検証が無効の間も、保存した結果は通知の振り分けと解析の証拠に使う（新しい行は追加しない）。

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| id | INTEGER | NO | AUTOINCREMENT | 主キー |  |
| name | VARCHAR(253) | NO | - | | 引いた名前（小文字、末尾のドットなし） |
| qtype | VARCHAR(8) | NO | - | | 種別。値: `MX` / `A` / `AAAA` |
| outcome | VARCHAR(16) | NO | - | | 結果。値: `exists` / `not_found` / `broken` |
| detail | TEXT | NO | - | | 1 行目が `name=<名前> type=<種別> outcome=<結果>`、続けて経路ごとの結果（リゾルバーごとの対照クエリと応答、権威 DNS ごとの応答。権威 DNS に問い合わせなかったときは `authoritative: not asked (only the OS resolver is used)` / `authoritative: not asked (the notice does not show mail of ours)`）を 1 行ずつ書いた証拠。4 KB まで。エージェントの証拠に使う |
| checked_at | DATETIME | NO | - | | 検証した日時 |

リレーション: なし。索引: `idx_dns_checks_lookup (name, qtype, checked_at)`。通知に使う結果は、名前と種別が同じで、通知の受信日時（無ければメールの日付。無い・未来なら現在）の 24 時間前から 48 時間後までの期間（両端を含む）に検証したもののうち最も早いもの。複数のジョブが同時に同じ名前を検証しても、同じ名前・種別・期間の行は 1 つだけ追加される（1 つの SQL 文で「無ければ追加」する）。`checked_at` は検証を終えた時刻で、その通知の期間の終わりより後なら期間の終わりにする。`checked_at` が `mail_keep_days` に再利用の期間（24 時間）を足した期間より前の行は、日次のクリーンアップで削除する。

### own_source_lookups

自分たちの送信元として、名前から自動で引いたアドレスと、SPF から得たアドレス・ホスト名の取得結果（メール判定仕様 2.7）。取得は種類と名前ごとに 1 行で、全監視アドレスで共有する（監視アドレスの列は無い。身に覚えのない返送通知の判定を有効にするかどうかは監視アドレスごとの設定で決まり、この表の行では決まらない）。完全に取得できたときの結果だけを保存する（ホスト名の種類では、A と AAAA の両方に答えがあったとき（アドレスの無い答えを含む）。SPF では評価を最後まで終えたとき。片方だけの答えや不完全な評価で保存済みの行を置き換えない）。

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| id | INTEGER | NO | AUTOINCREMENT | 主キー |  |
| kind | VARCHAR(16) | NO | - | 種類と名前で一意 | 種類。値: `smtp_host`（監視アドレスの SMTP サーバーの A / AAAA）/ `global_host`（設定 `own_sending_hosts` の名前の A / AAAA）/ `spf`（監視アドレスのドメインの SPF が指すアドレスとホスト名） |
| name | VARCHAR(253) | NO | - | 種類と名前で一意 | ホスト名または SPF のドメイン（小文字、末尾のドットなし） |
| addresses | TEXT | NO | - | | 見つかったアドレスと CIDR（正規化した文字列、1 行に 1 つ、改行区切り。無ければ空） |
| hosts | TEXT | NO | - | | 見つかったホスト名（`spf` の `a` / `mx` が指す名前だけ。改行区切り。無ければ空） |
| fetched_at | DATETIME | NO | - | | 取得を完了した日時 |

リレーション: なし。制約: `UNIQUE (kind, name)`。取得から 1 時間以内の行は問い合わせずに使い、取り直しに失敗したときは 14 日以内の行を使う。何も見つからなかった完全な答え（`addresses` も `hosts` も空）は、14 日以内の空でない行を置き換えない（その行をそのまま使い、`fetched_at` は更新しない）。`spf` の行のうち、範囲の上限（/8（IPv4）・/16（IPv6）より広い範囲、または範囲の合計が 2^24 個（IPv4）・2^112 個（IPv6）を超えるもの）を超える行は使わない（上限を設ける前に保存された行）。取得日時は時計が戻ると現在より後になることがあり、その行は新しいものとして扱わない（取得に失敗したときの代わりには使える）。どの設定からも参照されなくなった行は、纏めの最初の取得の前に設定を読み直して削除する。取得から 90 日を過ぎた行と、取得日時が現在より 1 日を超えて後の行は、日次のクリーンアップで削除する。

| model | TEXT | NO | - | | CLI が報告した実際のモデル（報告しなければ空） |
| reasoning_effort | VARCHAR(16) | NO | - | | CLI が報告した実際の推論レベル（報告しなければ空） |
| tokens_used | INTEGER | YES | - | | CLI が報告した消費トークン数（報告しなければ NULL） |
| command_count | INTEGER | YES | - | | エージェントが実行したコマンドの数（数えられなければ NULL） |
| started_at | DATETIME | YES | - | | 開始日時 |
| finished_at | DATETIME | YES | - | | 終了日時 |
| created_at | DATETIME | NO | - | | 作成日時 |

索引: `idx_agent_reports_group (group_key, id)`。
リレーション: `group_key` → `groups.group_key`（多対 1）。`agent_report_patterns.report_id` から参照される（1 対多）。

### agent_report_patterns

解析が決着した報告が扱ったグループのパターン（`bounces.pattern_key` と `dmarc_records.pattern_key`）。

| カラム名 | 型 | NULL | 既定値 | 制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| report_id | INTEGER | NO | - | 主キー（`report_id`, `pattern_key`）、`agent_reports.id`（報告削除時にカスケード削除） | 報告 |
| pattern_key | VARCHAR(16) | NO | - | 主キー（同上） | 報告が扱ったパターン |

リレーション: `report_id` → `agent_reports.id`（多対 1）。`pattern_key` は `bounces.pattern_key` または `dmarc_records.pattern_key` と同じ値（外部キー制約なし）。
