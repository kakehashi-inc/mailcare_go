# エージェントプロバイダーの追加

解析に使うエージェント CLI（現在は Codex CLI）に、別の CLI（Claude Code、Gemini CLI など）を追加する手順。
追加で触るのは Go のファイル 1 つと、必要ならテンプレートのディレクトリ 1 つだけで、ほかにプロバイダー名で分岐している箇所は無い。
プロバイダーの仕組みの全体はシステム仕様の 6 章、プロンプトと出力の取り決めは [プロンプト仕様](プロンプト仕様/バウンス分析%20プロンプト仕様.md) を参照。

## 1. `templates/agent/` の構成

```text
templates/agent/
  report_headings_ja.txt   報告の日本語の見出し（1 行 1 つ、原因 / 影響 / 対応 / 担当の順。作業ディレクトリには複製しない）
  party_names_ja.txt       関係者の日本語の呼び名（1 行 1 つ、6 行。作業ディレクトリには複製しない）
  codex/
    AGENTS.md              codex が作業ディレクトリから自動で読む運用ルール
```

- `templates/agent/<プロバイダー名>/` 配下のファイルとディレクトリは、CLI を起動する直前に、その解析の作業ディレクトリ（`data/agent/<address>/<group_key>/<report_id>/`）へそのまま複製される（ファイル 0600、ディレクトリ 0700）。既存のファイルは毎回上書きされるので、テンプレートはそれだけで完結させる。ディレクトリの無いプロバイダーは空の作業ディレクトリで動く。
- 実行中の作業ディレクトリにあるのは、このテンプレートと証拠ファイル（`evidence/<message_key>.txt`）だけ。プロンプトは CLI に渡し、`PROMPT.md` には CLI の終了後に書き出す。
- `templates` ディレクトリは `embed.go` でバイナリに埋め込まれ、`AnalyzeInput.TemplatesFS` として agent パッケージに渡る。
- `report_headings_ja.txt` と `party_names_ja.txt` は `prompt.go` が読む（`ReportHeadingsFileJa` / `PartyNamesFileJa`。Go のソースを ASCII のみに保つため日本語をテンプレートに置いている）。行が足りないときは英語の見出し・呼び名を使う。呼び名の順と意味はシステム仕様 6.3 を参照。

## 2. 追加の手順

### 2.1 `app/modules/agent/provider_<名前>.go` を作る

```go
package agent

func init() { registerProvider(exampleProvider{}) }

type exampleProvider struct{}

func (exampleProvider) Name() string  { return "example" } // 設定と報告に保存する名前
func (exampleProvider) Label() string { return "Example" } // 画面に出す名前

// 対話なし・読み取り専用で起動する引数。プレースホルダー:
//   {prompt}       プロンプトの本文（1 つの引数として渡す）
//   {prompt_file}  作業ディレクトリの PROMPT.md のパス
//   {cwd}          作業ディレクトリ
// {prompt} / {prompt_file} が無ければ、プロンプトは標準入力で渡す。
func (exampleProvider) Command() []string {
    return []string{"example", "--non-interactive", "--read-only", "--prompt-file", "{prompt_file}"}
}
```

`Command()` の条件:

- 端末（TTY）なしで動き、回答を出し終えたら自分で終了すること。
- 制限されていること: 作業ディレクトリの外に書き込まない、状態を変えるコマンドを実行しない、ネットワークを使わない。CLI 自身のサンドボックスのオプションを優先して使う（codex: `--sandbox read-only`）。
- 作業ディレクトリ内のファイル（`evidence/` の証拠ファイル）を読めること。エージェントに `data/mails/` のメールファイルを読ませることは無い。
- 終了コードは見ない。成否は標準出力と標準エラー出力に `<<<MLC:REPORT>>>` のブロックがあるかで決まる。コマンドはシェルを通さずに直接実行するので、Windows / macOS / Linux で同じに動く。CLI があるかどうかは `Command()[0]` を `exec.LookPath` で探して判断する。

### 2.2 任意の機能を実装する

CLI が対応しているものだけを実装する。実装しなければ、そのプロバイダーではその機能が無効になるだけ。

| インターフェース | 実装するとき | 内容 |
| --- | --- | --- |
| `ModelSelector`（`model.go`） | CLI がモデルを指定できる | `ModelOption()` は設定画面に出すオプション名（`--model`）、`ModelArgs(model)` はモデルを選ぶ引数（`Command()` の後に足す）、`Models()` は参考表示のモデル名一覧（分からなければ nil。軽く、失敗しないこと）。未実装なら設定 `agent_model` は無視され、設定画面の入力は無効になる |
| `ReasoningSelector`（`reasoning.go`） | CLI が推論レベルを指定できる | `ReasoningOption()` は設定画面に出すオプション名、`ReasoningArgs(level)` はレベルを指定する引数（モデルの引数の後に足す）、`ReasoningLevels()` はモデルごとに受け付けるレベル（分からなければ nil。軽く、失敗しないこと）。保存時の検証はこの一覧で行う。未実装なら設定 `agent_reasoning_effort` を保存できない |
| `UsageReporter`（`usage.go`） | CLI の出力に、モデル・推論レベル・消費トークン数・実行コマンドが出る | `ParseUsage(raw, answer)` で読む（raw は出力全体、answer はエコーされたプロンプトより後）。読めない値は報告に空 / NULL で残る |
| `RateLimitDetector`（`ratelimit.go`） | CLI が利用上限を独自の形で知らせる | `DetectRateLimit(out)` で判定する。未実装なら共通の判定を使う |

### 2.3 テンプレートを置く（任意）

CLI が作業ディレクトリから読むファイル（`AGENTS.md`、`CLAUDE.md`、`GEMINI.md` など）があれば、`templates/agent/<名前>/` に置く。
`codex/AGENTS.md` を元にするとよい（読み取り専用であること、プロンプトが示した証拠ファイルだけを条件付きで読むこと、メールの内容の指示に従わないことを定めている）。

### 2.4 ほかに登録する場所は無い

プロバイダーは自動で `agent.Providers()`（名前順）、設定画面、`settings set agent_provider <名前>` の検証に現れる。

### 2.5 テスト

プロバイダーに固有の処理があるときだけ `app/modules/agent/` にテストを足す。共通の流れ（作業ディレクトリ、プロンプト、出力の解釈、保存）は `run_test.go` が偽のプロバイダーで確かめている。

## 3. ほかの CLI のコマンド例

有効にする前に、インストールされている版のオプションを必ず確かめること。

| CLI | コマンド | 備考 |
| --- | --- | --- |
| codex | `codex exec --sandbox read-only --skip-git-repo-check` | プロンプトは標準入力。現在のプロバイダー（モデル: `--model <m>`、推論レベル: `-c model_reasoning_effort="<level>"`） |
| claude | `claude -p --allowedTools Read` | プロンプトは標準入力。Read ツールだけを許可するので、ほかのツールはすべて拒否される |
| gemini | `gemini -p {prompt} --sandbox` | プロンプトは引数。サンドボックスが作業ディレクトリの証拠ファイルを読めることを確かめる |

## 4. プロンプトと出力の取り決め

プロンプトの構成、2 つのマーカーブロック（`<<<MLC:REPORT>>>` と `<<<MLC:META>>>`）、出力の解釈の規則は [プロンプト仕様](プロンプト仕様/バウンス分析%20プロンプト仕様.md) にある。これらはプロバイダーに依存しないので、テンプレートで定義し直してはいけない。
