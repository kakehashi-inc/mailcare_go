# システム設計書 - システム名をここに記載

本書はテンプレートの初期状態におけるシステム設計を記述したものです。プロジェクト固有の設計に合わせて更新してください。

## 1. 用語定義

| 用語（日本語） | English | 説明 |
| --- | --- | --- |
| 利用者 | User | ブラウザで Web 画面を操作する人 |
| 運用者 | Operator | サーバーを起動・停止し、データディレクトリを管理する人 |
| データディレクトリ | Data directory | DB ファイルなど実行時データを置くディレクトリ |
| マイグレーション | Migration | DB スキーマを段階的に変更する SQL ファイル |
| 設定 | Setting | 既定値を上書きするサーバー設定（`settings` テーブル） |
| トークン | Token | API サーバーの Bearer 認証に使うアクセストークン（`tokens` テーブル） |
| デフォルトトークン | Default token | デフォルトトークンが無い状態で起動したときに自動作成されるトークン（識別子 `default`） |
| コントロールエンドポイント | Control endpoint | ローカルからのみ利用できる停止・状態確認用 HTTP エンドポイント |
| SPA | Single Page Application | バイナリに埋め込まれて配信される React 製の Web 画面 |

## 2. 全体構成

```text
+-------------------------------------------------------------+
| develop_app (single binary)                                 |
|                                                             |
|  main.go ---- kong CLI ----> app/modules (commands)         |
|                                  |                          |
|                                  v                          |
|                           app/workers (HTTP servers)        |
|                             |  API server (api_port)        |
|                             |    /api/v1/*   JSON API       |
|                             |    /control/*  loopback only  |
|                             |  Web server (web_port)        |
|                             |    /api/v1/*   JSON API       |
|                             |    /*          embedded SPA   |
|                             v                               |
|                    app/models  <---> SQLite (data dir)      |
|                                                             |
|  embed.go: app/migrations/*.sql, frontend/dist/**           |
+-------------------------------------------------------------+
```

- サーバー、CLI、Web 画面、マイグレーションを 1 つの実行ファイルにまとめ、配布・起動を単純化しています。
- HTTP サーバーは API 用と Web 用の 2 リスナーです。ハンドラは `core` で共有し、認証はサーバーごとのミドルウェアに置きます。API サーバーは Bearer トークン認証、Web サーバーは認証なし（ユーザー認証は持たない）です。
- パッケージ間の依存は `main -> workers -> modules -> models` の一方向です。`modules` から `workers` のサーバーを起動する必要があるため、`workers` が `init()` で `modules.StartServer` に関数を登録します（循環参照の回避）。

## 3. ディレクトリと責務

| パス | 責務 |
| --- | --- |
| `main.go` | 起動パラメータの定義と解析（kong）。埋め込みアセットとバージョンを `modules` に渡す |
| `embed.go` | `app/migrations/*.sql` と `frontend/dist` の埋め込み |
| `app/migrations` | goose 形式の SQL マイグレーション |
| `app/models` | テーブルごとのデータ構造とアクセス関数 |
| `app/modules/constants.go` | アプリ名、既定値、設定キーなどの定数 |
| `app/modules/datadir.go` | データディレクトリの決定と作成 |
| `app/modules/db.go` | SQLite の接続とマイグレーションの適用（`OpenDB` 時に自動実行） |
| `app/modules/tokens.go` | トークンの生成・検証（識別子の採番、有効期限の解釈、Bearer 検証） |
| `app/modules/fileutil.go` | 乱数ヘルパー（`RandomHex`） |
| `app/modules/cli.go` | `token` / `service` サブコマンドの実装と表示 |
| `app/modules/service.go` | サーバー起動関数の登録先と、ローカルサーバーへの停止・状態確認リクエスト |
| `app/modules/errors.go` | CLI の終了コードと `ExitError` |
| `app/workers/server.go` | 両サーバーのライフサイクル（設定の解決・保存、リスナー、シグナル処理、停止）、共有ハンドラ、JSON 応答ヘルパー |
| `app/workers/api_server.go` | API サーバーのルーティングとミドルウェア（Bearer 認証、ループバック制限）、コントロールエンドポイントのハンドラ |
| `app/workers/web_server.go` | Web サーバーのルーティングと SPA 配信 |
| `frontend/` | Web 画面（後述） |

## 4. CLI

`develop_app [--data-dir DIR] <command>`

| コマンド | 説明 |
| --- | --- |
| `token create --identifier ID [--name NAME] [--expires DUR\|TIME] [--json]` | トークンを作成し、値を表示する（最初の 1 件は自動的にデフォルト） |
| `token list [--json]` | トークン一覧（値はマスク表示、デフォルトに `*`） |
| `token show ID [--json]` | トークンの詳細（値を平文で表示） |
| `token delete ID [-y]` | トークンを削除する。デフォルトを削除しても他のトークンは昇格させず、次回起動時に識別子 `default` のトークンがあればそれをデフォルトに設定、無ければ作成する |
| `service start [--api-listen ADDR] [--web-listen ADDR] [--api-port N] [--web-port N]` | API サーバーと Web サーバーを起動する。デフォルトトークンが無ければ、識別子 `default` の既存トークンをデフォルトに設定するか、無ければ作成して値をログに出力する |
| `service stop [--api-port N]` | 起動中のサーバーを停止する（API サーバーのコントロールエンドポイントへ接続。`--api-port` の既定値は 8081） |
| `service status [--api-port N]` | 起動中のサーバーの状態を表示する（`--api-port` の既定値は 8081） |
| `version` | バージョンを表示する |

- `--data-dir` はグローバルフラグで、どのコマンドにも指定できます。
- 終了コードは `app/modules/errors.go` に定義しています（0: 正常終了、1: 一般エラー、2: 引数エラー、3: 設定エラー、4: 認証エラー、5: 実行エラー、6: ファイル I/O エラー、7: タイムアウト）。コマンドが `ExitError` を返した場合はそのコード、それ以外のエラーは 1 で終了します。

### 4.1 データディレクトリの決定

`--data-dir` > `<実行ファイルのディレクトリ>/data` の順で決定します。存在しない場合はパーミッション `0700` で作成します。

### 4.2 設定の解決と保存

`service start` の `--api-listen` / `--web-listen` / `--api-port` / `--web-port` は次の順で解決します。

1. コマンドライン引数（指定あり）
2. `settings` テーブルに保存された値
3. コードの既定値（`0.0.0.0` / `0.0.0.0` / `8081` / `8080`）

API ポートと Web ポートが同じ値に解決された場合は起動エラーになります。解決後、既定値と異なる値のみを `settings` テーブルに保存し、既定値と等しい場合は既存の行を削除します。これにより、既定値をコードで変更した際に古い保存値が残って上書きし続けることを防ぎます。

## 5. HTTP サーバー

### 5.1 リスナー

- API サーバーと Web サーバーは別のリスナーで、それぞれ独立した待受アドレス・ポートを持ちます。
- API サーバーは、`--api-listen` が `0.0.0.0` / `127.0.0.1` / `localhost` 以外の特定インターフェースの場合、同じポートで `127.0.0.1` にも追加でリッスンし、コントロールエンドポイントへローカルから到達できるようにします。
- `ReadHeaderTimeout` を設定し、ヘッダー送信が遅いクライアントによる接続の占有を防ぎます。
- `SIGINT` / `SIGTERM` またはコントロールエンドポイントからの停止要求で、猶予時間（5 秒）内に進行中のリクエストを完了させてから停止します。

### 5.2 エンドポイント

| サーバー | メソッド | パス | 認証 | 説明 |
| --- | --- | --- | --- | --- |
| API | GET | `/api/v1/health` | Bearer | 稼働確認。`{"status":"ok","version":"<version>"}` を返す |
| Web | GET | `/api/v1/health` | なし | 同上（Web 画面のバージョン表示用） |
| API | POST | `/control/shutdown` | ループバックのみ | 正常停止を開始する |
| API | GET | `/control/status` | ループバックのみ | 状態（名前、バージョン、両サーバーの待受アドレス、稼働時間、トークン数）を返す |
| Web | GET | `/*` | なし | 埋め込み SPA。存在するファイルはそのまま配信し、それ以外は `index.html` を返す |

- API サーバーの `/api/v1/` 配下は `Authorization: Bearer <token>` を `tokens` テーブルと照合し（未知・期限切れは 401）、認証したトークンをリクエストコンテキストに載せてハンドラへ渡します。`/api/v1/` と `/control/` 以外のパスには 404 を返します。`/control/` 配下はミドルウェアで接続元が `127.0.0.1` / `::1` かを検査し、それ以外は 403 を返します。
- Web サーバーは認証を持たず、Web 画面は同一オリジンの Web サーバー側 `/api/v1/health` を呼びます。ハンドラは両サーバーで共有します。
- `.webmanifest` / `.ico` / `.woff2` の MIME タイプは OS のテーブルに依存せず明示的に登録しています。

### 5.3 API の追加方法

1. `app/workers/server.go` の共有ハンドラとして `func (c *core) handleXxx(w http.ResponseWriter, r *http.Request)` を実装する。API サーバー側では `tokenFrom(r)` で認証済みトークンを取得できる。
2. `app/workers/api_server.go` の `apiHandler()` と、Web 画面から呼ぶ場合は `app/workers/web_server.go` の `webHandler()` に `mux.HandleFunc("GET /api/v1/xxx", c.handleXxx)` を追加する。
3. 応答の型を `frontend/src/types.ts` に、呼び出し関数を `frontend/src/api/client.ts` に追加する。
4. 本書の 5.2 の表を更新する。

## 6. データベース

- SQLite（`modernc.org/sqlite`、CGO 不要）。DSN で `busy_timeout(5000)`、`journal_mode(WAL)`、`foreign_keys(1)` を設定しています。
- DB ファイルはデータディレクトリ内の `develop_app.db` です。
- スキーマは goose により管理します。`OpenDB` は接続時に未適用のマイグレーションを自動適用するため、サーバー起動時にスキーマが常に最新になります。- テーブル定義は [テーブル定義.md](テーブル定義.md) を参照してください。

### 6.1 マイグレーションの追加方法

1. `app/migrations/000N_<description>.sql` を連番で追加する（適用済みのファイルは編集しない）。
2. `-- +goose Up` / `-- +goose Down` の両方を書き、各文を `StatementBegin` / `StatementEnd` で囲む。
3. 対応するモデルを `app/models/<table>.go` に追加し、テーブル定義.md を更新する。

## 7. フロントエンド

### 7.1 構成

- Vite + React 19 + TypeScript + Tailwind CSS v4（`@tailwindcss/vite`）+ react-router-dom + i18next。
- `yarn build` の出力 `frontend/dist` を Go バイナリに埋め込み、サーバーが配信します。
- `main.tsx` で Router、i18n、CSS（`scss/tailwind.css`、`scss/app.scss`）を読み込みます。

### 7.2 テーマ（ライト / ダーク）

- 判定は CSS のみで行い、JavaScript による切り替えやクラスの付け替えはありません。
- `scss/tailwind.css` で `:root { color-scheme: light dark; }` を宣言し、`frontend/tailwind.config.js` の色トークンを `light-dark(ライト色, ダーク色)` で定義しています。ブラウザは OS の `prefers-color-scheme` に従っていずれかの色を採用します。
- ビルド時に Lightning CSS が `light-dark()` を `prefers-color-scheme` のメディアクエリを使った等価な CSS に変換するため、`light-dark()` 未対応のブラウザでも動作します。
- Tailwind v4 は `tailwind.config.js` を自動で読み込まないため、`scss/tailwind.css` の `@config` で明示的に読み込んでいます。`darkMode: "media"` は Tailwind の `dark:` バリアントも OS 設定に追従させるための指定です。
- セマンティックトークン一覧:

| トークン | 用途 |
| --- | --- |
| `canvas` | ページ背景 |
| `surface` | カード・ヘッダーなど浮き上がった面 |
| `ink` | 主要テキスト |
| `muted` | 補助テキスト |
| `line` | 罫線・境界線 |
| `accent` / `accent-hover` / `accent-contrast` | 強調色、そのホバー色、強調色上のテキスト色 |

### 7.3 多言語対応

- 対応言語は `src/constants.ts` の `SUPPORTED_LANGS`（`ja`、`en`）で定義し、翻訳は `src/i18n/ja.json` / `en.json` に置きます。
- 初期言語は「localStorage に保存された選択（`develop_app.lang`）> ブラウザの言語設定（`navigator.languages` を順に照合）> 日本語」の順で決定します。保存はヘッダーの地球アイコンから開くドロップダウンで言語を明示的に選択したときのみ行うため、選択していない利用者は常にブラウザ設定に追従します。
- 言語変更時は `<html lang>` も更新します。
- 翻訳キーは `src/i18n/i18next.d.ts` により `ja.json` の構造で型付けされ、存在しないキーは `yarn lint` で検出されます。

### 7.4 画面

| パス | コンポーネント | 内容 |
| --- | --- | --- |
| `/` | `HomePage` | `Hello world` と案内文を表示する |
| それ以外 | `NotFoundPage` | 404 とホームへのリンクを表示する |

共通ヘッダー（`Header`）にはアプリ名、サーバーから取得したバージョン、言語切り替え（`LanguageSwitch`: 地球アイコンのクリックでドロップダウンを開き、現在の言語にチェックを表示。外側クリックまたは Escape で閉じる）を表示します。

## 8. ビルドとリリース

- `make`（`make build`）: フロントエンドをビルドしてから Windows / Linux / macOS の amd64 / arm64 向けにクロスビルドし、`bin/` に出力します。
- `make pack`: 各バイナリを zip にまとめます。
- バージョンは `Makefile` の `VERSION` を `-ldflags "-X main.version=..."` で埋め込みます。
- `make lint`: `go vet` / `staticcheck` / `yarn lint` をまとめて実行します。`make test`: `go test ./...` を実行します（どちらもフロントエンドを先にビルドします）。
