# 画面仕様 - MailCare

本書は Web 画面（SPA）の画面ごとの振る舞い（表示する内容、操作、ボタンを押せる条件、案内・警告と文言のキー、画面での入力の検査、自動更新、一般利用者と管理者の出し分け）を定める。サーバーの規則（API の形、権限の検査、入力の検証、ジョブ）は [システム仕様](システム仕様.md)、メールの判定の規則は [メール判定仕様](メール判定仕様.md)、フロントエンドの構成（技術、ディレクトリ、言語ファイルのキーの決め方）は [システム仕様](システム仕様.md) 10 章に記載する。画面の振る舞いを変更した場合は本書を更新してください。

1 章のユニバーサルデザインはすべての画面の前提の規則、2 章は画面に共通の事項、3 章以降は画面（パス）ごとの仕様である。

## 1. ユニバーサルデザイン

すべての画面は次の規則に従う。

- 本文は 16px、補足情報（表の備考・ジョブ履歴の詳細など）は 14px。行間 1.5 以上、コントラスト比 4.5:1 以上。色だけに頼らず、状態はアイコン + 文字でも示す。
- ボタン（既定の二次ボタン）は塗り（`well`）と、背景に対して 3:1 以上のコントラストの枠線（トークン `control`。WCAG 1.4.11）を持ち、カードの上でもボタンと分かるようにする。
- ページャー（共通部品 `Pagination`。メール一覧・アラート一覧・ジョブ履歴で一覧の上と下に置く）: 表示中の範囲（「N 件中 a〜b 件」）と「現在 / 全ページ数」、アイコンだけのボタンで最初・前・次・最後のページへ移る（ボタンには「最初のページ」などの読み上げ名とツールチップを付ける。移れない向きのボタンは無効にする）。
- すべての操作要素にフォーカスリング、`aria-label`、44px 以上のタップ領域を持たせる（例外: アラート一覧のバッジ行に置く状態変更ボタンはバッジと同じ大きさ（ボタンのサイズ `xs`）。詳細画面にも同じ操作がある）。表（共通部品 `Table`）は幅が狭いとき（md 未満）カード表示に切り替える。
- ダイアログのボタン（共通部品 `ConfirmDialog` と、対応済・無視の `GroupStateDialog`）は OS とブラウザのダイアログに合わせ、横並びでは確定を左・キャンセルを右に置く（取り消せない操作を押しやすい右側に置かない）。幅が狭く縦に並べるときは確定を上・キャンセルを下にする。確認ダイアログを開いたときのフォーカスはキャンセルに、対応済・無視のダイアログでは最初の選択肢に置く。開いている間はフォーカスをダイアログの中に閉じ込め（`useFocusTrap`。Tab / Shift+Tab は最初と最後の操作要素で折り返し、それでも外に出たフォーカスは戻す。ボタンだけでなくチェックボックス・ラジオボタン・入力欄も対象で、ラジオボタンの組には選択中のボタンで入る）、閉じたら開く前の要素に戻す。Esc はキャンセルと同じ。
- Markdown（分析結果）は `react-markdown` で表示し、`rehype` 系のサニタイズは使わず（内部生成のため）、リンクは新規タブで開く。
- 一覧の並び替えと表示条件: グループ一覧（5.3）の並び替え（最終日時の新しい順 / 古い順、件数、重大度）はサーバーで行い（`sort`）、表示範囲・状態・カテゴリ・対応者区分・検索語・並び順・ページは URL のクエリに保持する。

## 2. 共通

### 2.1 レイアウトと表示

- 全画面レスポンシブ（スマートフォン縦 360px〜、タブレット縦 768px、タブレット横 1024px、PC 1280px 以上）。
- 言語とテーマは利用者の設定（`users.language` / `users.theme`。[システム仕様](システム仕様.md) 4 章）に従い、ブラウザからの自動判別や localStorage への保存はしない。ログイン前の画面は日本語・自動テーマ。テーマは `light-dark()` トークンを使い、`auto` は `color-scheme: light dark`（ブラウザの設定に追従）、`light` / `dark` は `<html>` に `color-scheme` を固定して切り替える。
- 日時はログイン中の利用者のタイムゾーンで変換して表示する（API の日時は UTC。[システム仕様](システム仕様.md) 4 章）。サーバーのローカル時刻で実行する時刻（同期時刻、通知時刻、クリーンアップ時刻、確認メールの送信時刻）の設定欄には、その旨とサーバーのタイムゾーンを表示する（9.2・9.3・9.4）。
- 利用者の入力項目の並びは全画面で統一する: ユーザー名 → 表示名 → メールアドレス → 言語 → タイムゾーン → テーマ →（管理者の利用者管理のみ）役割 → パスワード。

### 2.2 ナビゲーション（ヘッダー）

- 並び: `ブランド（MailCare、クリックでダッシュボード）` `バージョン` | `アラート` `メール` `ツール` `ジョブ` `設定` | 利用者名。アプリ名・バージョン・各アイコンはバー内で上下中央に揃える。
- 設定はクリックで説明付きの設定メニュー画面 `/settings`（9.1）へ遷移する。ドロップダウンは持たない。
- 利用者名はアイコンなしのドロップダウンで、クリックするとプロフィール / ログアウトを表示する。スマートフォン幅でもハンバーガーメニューに入れず右端に表示し、長い名前は省略記号で切り詰める。
- 言語切替のアイコンは置かない（言語はプロフィールで設定する。9.8）。
- 幅 1024px 未満ではハンバーガーメニューに畳む（設定は 1 項目のみで、下位項目は設定メニュー画面で選ぶ）。
- ツール・ジョブ・設定は管理者だけに表示する（2.3）。

### 2.3 権限による表示の違い

- 操作の権限と、API が一般利用者に返さない値は [システム仕様](システム仕様.md) 4 章の権限の表と 9.2。画面はそれに合わせて表示を出し分ける。
- 管理者専用の画面はツール（7 章）、ジョブ（8 章）、設定（9 章。プロフィールを除く）。一般利用者にはナビゲーションに表示せず、URL を直接開いた場合は「管理者のみ」の案内を表示する。
- アラート・メール・ダッシュボードなど設定以外の画面でも、一般利用者には「メールアドレスを追加」への導線を出さず、未登録時は「登録されていない」事実だけを表示する（「管理者に依頼してください」のような文言は出さない）。
- 接続先やサーバーの名前を含むエラー文（同期のエラー、確認メールの送信・到着確認・削除のエラー）は管理者だけに表示し、一般利用者には詳細の無い表示にする。管理者だけの操作（分析、確認メールの今すぐ送信・到着確認など）のボタンは一般利用者には出さない。どれも各画面の節に記す。

### 2.4 言語と用語

- 画面の文言は言語ファイル（`frontend/src/i18n/ja.json` / `en.json`）から利用者の言語で表示する。キーの節と命名、API のエラーの表示の規則は [システム仕様](システム仕様.md) 10.1 の「言語ファイル」。本書が示すキー（`page.dashboard.probeFailure` など）は言語ファイルの完全なキー。
- 画面の語は [システム仕様](システム仕様.md) 1 章の用語定義に揃える（再判定、再確認、送信元、確認メール、送信確認、同時実行数など。英語の画面は同じ表の English の語）。
- 対応者区分の表示（`sender` / `recipient` / `domain`）は、分析結果の関係者の呼び名（[システム仕様](システム仕様.md) 6.3 の表の 1・2・4）に揃える。

### 2.5 共通の部品

ページャー、ダイアログ、Markdown の規則は 1 章。

- 自動更新（`usePolling`）: ジョブが動いている間は 3 秒間隔で読み直し、タブが非表示の間は止める。ジョブ画面の間隔は 8 章。
- ジョブの一覧（`JobList`。ジョブ画面とダッシュボード）: メールアドレスの欄は、削除済みのアドレスのジョブ（API の `mailbox_deleted`。[システム仕様](システム仕様.md) 7.1）を「削除済みのメールアドレス」（`component.jobList.deletedMailbox`）、親の無い展開ジョブを「すべてのメールアドレス」（`component.mailboxSelect.all`）と表示する。
- ジョブの進捗（`JobProgressLog`。ジョブ画面とグループ詳細の分析中の表示）: 進捗の各行（[システム仕様](システム仕様.md) 7.1）のタブの前の時刻を、利用者のタイムゾーンの `MM-dd HH:mm:ss` に整形して時刻列として表示する。高さを制限したスクロール領域で、最下部を見ている間は新しい行に合わせて自動でスクロールし、利用者が上へスクロールしている間は位置を保つ。
- スイッチ（`ToggleField`）: オン / オフのスイッチは全画面共通の部品で、スイッチを左に置いてラベルと補足をすぐ右に並べ、ラベルのクリックでも切り替わる。

## 3. 初期設定とログイン

### 3.1 初期設定（`/setup`）

- 利用者が 0 人のときに表示する（[システム仕様](システム仕様.md) 4 章）。
- 初期管理者を作成する: ユーザー名、表示名、メールアドレス、言語、タイムゾーン、テーマ、パスワード。言語を変えると画面の言語が即時に切り替わる。

### 3.2 ログイン（`/login`）

- ユーザー名またはメールアドレスと、パスワードでログインする。
- 「ログイン状態を保持する」のチェックボックス（既定オフ。補足「共有の端末では使用しないでください。」）。Cookie の有効期限と試行制限は [システム仕様](システム仕様.md) 4 章。

## 4. ダッシュボード（`/`）

- 説明「監視中のメールアドレスと、対応が必要なバウンスの状況です。」
- 上部の合計: メールアドレス、未対応、再確認、受信メール、処理対象、迷惑メール。グループ化待ちは 1 件以上のときだけ。「再確認」は「対応済（再確認）」と「無視（再確認）」の合計。
- メールアドレスごとのカード: 1 段目に未対応・再確認（アラートのカードと同じ）、2 段目に受信メール・処理対象・迷惑メール（メールのカードと同じ）、グループ化待ち（1 件以上のとき）、最終同期、状態（同期のエラー文は管理者だけに表示し、一般利用者には「最後の同期に失敗しました。」）、最新の確認メールの状態（全利用者）。
  - 無効なアドレスには「このメールアドレスは無効のため、自動同期の対象外です。」を添える。
  - 未対応の件数（`stats.groups`）は対応対象の一覧の件数で、対象外グループの件数は表示しない。
  - アドレスの「同期中」の表示は `busy_mailbox_ids` で全利用者に出す。
- 実行中のジョブと最近のジョブ（管理者のみ。「すべてのジョブ」でジョブ画面へ）。
- スケジュール: 次回同期と同期時刻。未設定なら「スケジュール未設定」。
- AI エージェント: プロバイダー名と状態のアイコン（有効で CLI があれば緑、無効なら灰色、CLI が無ければ警告色）。自動分析が無効のときの注記（「自動分析は無効です」と一般設定へのリンク）と、CLI が見つからないときの警告（「AI エージェントの CLI が見つかりません」）は管理者のみに表示し、一般利用者にはアイコンの色だけで示す。
- 確認メール: 障害（障害と送信失敗）・遅延があればお知らせの帯（`page.dashboard.probeFailure` / `page.dashboard.probeDelay`）。確認メールが設定済みか確認メールの記録があれば確認メールのカード（状態。最後の到着確認が失敗していれば「到着確認に失敗」（管理者にはエラー文も）。有効なら次回送信・次回到着確認・判断時間）。
- 同期の操作はツール（7 章）から行い、ダッシュボードには置かない。

## 5. アラート

### 5.1 メールアドレスの選択（`/alerts`）

- メールアドレスの選択（カード / セレクト）。カードに未対応と再確認（「対応済（再確認）」と「無視（再確認）」の合計）の件数を表示する。
- 先頭に確認メールの件数付きのカード（`page.alerts.probeCard`。最後の到着確認が失敗していれば「到着確認に失敗」、管理者にはエラー文も）を置く。

### 5.2 確認メール（`/alerts/probes`）

- 説明 `page.probes.description`。
- 件数: 障害・送信失敗・遅延・到着待ち・回復・対応済（回復と対応済は直近 7 日）。
- メールアドレスごとの最新の確認メール。
- スケジュール: 送信時刻とサーバーのタイムゾーン、判断時間、最後 / 次回の送信と到着確認。
- 一覧: タブは 未対応 / 遅延・障害の履歴 / すべて。列は送信時刻（件名と同じサーバー時刻、手動は「手動」）・状態（回復・対応済には到達した段階も表示）・遅延（「N で到着」/「未着 N」）・到着日時・最終確認・備考（送信のエラー文と差出人の不一致（管理者のみ）、対応の理由・詳細・対応者。システムが閉じたものは「自動で対応済」）。
- 対応済にする操作: すべての利用者が、遅延・障害・送信失敗の確認メールを理由を選んで対応済にできる（ダイアログ `ProbeResolveDialog`。グループの状態変更のダイアログ（5.5）と同じ動き）。理由の選択肢と検査は [システム仕様](システム仕様.md) 7.6 の「手動の対応」。
- 管理者の操作: 「今すぐ送信」（確認メールが有効で、送るメールアドレスがあるとき）と「今すぐ到着確認」（確認メールが有効で、未対応の確認メールがあるとき）。条件を満たさなければボタンを押せず、理由をツールチップに出す。
- 警告: 最後の到着確認が失敗していれば、管理者にはエラー文付き、一般利用者にはエラー文なしの警告を出す。確認メールを確認メールサーバーから削除できなかったとき（`probe_last_delete_error`）は、管理者に理由付きの警告を出す。

### 5.3 グループ一覧（`/alerts/:mailboxId`）

- 表示範囲: 対応対象 / 対象外（既定は対応対象のみ）。表示範囲には件数を表示しない。範囲ごとの抽出条件は [システム仕様](システム仕様.md) 9.2 の `scope`。対象外グループを対応済・無視にすると対応対象側の該当タブに現れ、未対応に戻すと対象外に戻る。
- 状態タブ（対応対象のみ）: 未対応 / 対応済 / 対応済（再確認） / 無視 / 無視（再確認）。タブごとに件数を表示する。「（再確認）」のタブは再確認待ち（[メール判定仕様](メール判定仕様.md) 4.5）のグループで、再確認待ちのグループは元の状態のタブには出さない（どれか 1 つのタブにだけ載る）。URL の `state` は `resolved_recheck` / `ignored_recheck` も取る。
- 対象外では状態タブを出さず、説明 `page.alerts.excludedHint` と一覧だけを表示する。範囲を切り替えると状態の指定は解除される。
- 絞り込みと並び: カテゴリ・対応者区分の絞り込み、検索（「対応単位、判定元、ドメイン、診断文で検索」）、並び順（最終日時（新しい順）/ 最終日時（古い順）/ 件数（多い順）/ 重大度）。並び替えと URL への保持は 1 章。
- ページング: 50 件ずつ（一覧の上と下にページャー。URL の `page`）。条件・並び・タブを変えると 1 ページ目に戻る。状態変更などで今のページが空になったら最後のページへ移る。
- 各行: カテゴリのバッジ、対応単位（IP / 差出人アドレス / ドメイン）、判定元（ブラックリスト名 / 宛先ドメイン）、件数・宛先数（0 件なら出さない）・IP 数・最終日時・重大度・要約。最新の分析が分析不可のグループには「分析不可」バッジ（`report_unanalyzable`。5.4）。
  - 表示名はカテゴリごとに翻訳して組み立てる（例: 「送信 IP のブロック: 203.0.113.5（spamhaus.org）」）。
  - 見出しがグループ詳細へのリンクで、行全体を覆う（行のどこを押しても詳細へ移動する）。
  - 対応済・無視の行には、選んだ理由と詳細を 2 行まで表示する。
- 状態変更のボタン（対応対象の各行。全利用者。対象外の一覧には出さない）: バッジ行の右端に、バッジと同じ大きさで出し、詳細を開かずに変更できる。
  - 表示は移る先の状態名と、詳細画面のボタンと同じアイコン。未対応タブでは「対応済」「無視」、対応済・無視のタブでは「未対応」、「（再確認）」のタブでは「未対応」「対応済」「無視」（新しい判断）。読み上げ名は「〇〇を対応済にする」などの操作名。
  - 変更は 5.5 のダイアログを経る（`PUT .../groups/{key}/state`）。変更後は一覧とタブの件数を読み直す。

### 5.4 グループ詳細（`/alerts/:mailboxId/groups/:groupKey`）

- 概要: カテゴリ、対応単位、判定元、対応対象かどうか。対応済・無視なら対応内容または判断理由と詳細。
  - 再確認待ちなら状態バッジを「対応済（再確認）」「無視（再確認）」にし、再確認が必要になった理由の注記を出す。
  - 確度が `low` の報告があれば、概要のバッジ欄にも「要確認」バッジを出す。最新の分析が分析不可のグループには、見出しに「分析不可」バッジを出す（`report_unanalyzable`）。
  - 未対応の対象外グループは状態バッジを出さず、「対応済にする / 無視すると対応対象の一覧に移る」旨を添え、パンくずは対象外の一覧へ戻る。対応対象に移った対象外グループには「未対応に戻すと対象外の一覧に戻る」旨を添える。対象外グループには自動では分析しない旨を表示する。
  - 概要カードの下部に「レポートを表示」（`GET .../groups/{key}/report` の PDF をダウンロード）と「ダウンロード」（`GET .../groups/{key}/export` の ZIP）を置く（全利用者。内容は [システム仕様](システム仕様.md) 5.8・9.2）。
- 対応履歴: 新しい順に状態・日時・変更者・選んだ理由・詳細。無ければその旨。
- 統計: 宛先・IP・MTA の一覧。
- 分析結果: Markdown 表示（1 章）。確度が `low` の報告には「要確認」バッジ。CLI が報告したモデル（推論レベル）・トークン数・コマンド実行数（不明なら「-」）。分析結果の状態バッジは「分析中 / 分析済み / 分析エラー」。
  - 分析ボタン（管理者のみ。対応対象かどうかに関係なく表示する）: 完了した報告が無ければ「分析」、あれば「再分析」、実行中は「分析中」で押せない。エージェントの CLI が無いか利用上限が続いている間（設定 API の `analyze_refusal`）も押せず、理由をツールチップに出す。実行中は分析のジョブの進捗（2.5 の `JobProgressLog`）を表示する。
  - 過去の分析結果（「過去の分析結果（N 件）」）。
  - 直近の失敗があればその注記: 分析不可（`unanalyzable`: 利用上限・中止以外の失敗。`agent.FailureSettles`）なら理由と「新しいパターンの通知が届くまで自動では分析しない」旨、利用上限なら「分析待ちのまま次回に分析する」旨、それ以外（中止）はエラー文。
- 元メール一覧（→ メール詳細）: API が返す新しい順の最大 200 件（[システム仕様](システム仕様.md) 9.2）。全件はメール一覧の `group` 絞り込み（6.1）で見る。
- 状態変更（全利用者）: ボタンは「未対応に戻す」「対応済にする」「無視する」のうち今の状態以外。再確認待ちなら 3 つとも。どの変更も 5.5 のダイアログを経る。変更後は詳細を読み直す。

### 5.5 状態変更のダイアログ（一覧と詳細で共通）

- 対応済・無視（`GroupStateDialog`）: 見出しは操作名（「〇〇を対応済にする」）。対応済は対応内容、無視は判断理由のラジオボタン（必須。最後が「その他」）と、詳細の textarea（任意、2,000 文字まで。対応済は常に、無視は「その他」を選んだときだけ表示）。
  - 未選択で確定すると必須のエラーを出す。キャンセル（ボタン・Esc）は何も保存しない。ダイアログの外を押しても閉じない（入力が消えないように）。変更に失敗したら通知を出し、ダイアログは開いたまま。
  - 選択肢のコードとサーバーでの検査は [システム仕様](システム仕様.md) 5.9。
- 未対応に戻す: 確認ダイアログ（`ConfirmDialog`）を出す。見出しは「〇〇を未対応に戻す」、本文は対応済なら「対応内容と詳細は消去されます。対応履歴には残ります。」、無視なら「判断理由と詳細は消去されます。対応履歴には残ります。」。

## 6. メール

### 6.1 メールアドレスの選択とメール一覧（`/mails`、`/mails/:mailboxId`）

- メールアドレスの選択: カードに受信メール（`stats.messages`）・処理対象（`stats.target_messages`）・迷惑メール（`stats.junk_messages`）の件数を並べて表示する。
- メール一覧: 検索（「件名、差出人、宛先で検索」）、種類のタブ（すべて / 処理対象 / 迷惑 / その他。件数付き。URL の `kind`。処理対象と迷惑の範囲はカードの件数と同じで、どのメールがどのタブに載るかは [メール判定仕様](メール判定仕様.md) 1 章）、グループでの絞り込み（`group`）、ページング（一覧の上と下にページャー）。

### 6.2 メール詳細（`/mails/:mailboxId/:messageKey`）

- 本文カードはタブ切替で、順に「ヘッダー」（常に表示）、テキストセクション（`text_sections` の要素ごとに 1 タブ。MIME 順）、HTML セクション（`html_count` 個。n 番目のタブは `.../html/{n}` をセクションごとの sandbox iframe で表示）。
- 同種のセクションが 1 つなら「テキスト」「HTML」、2 つ以上なら「テキスト 1」「テキスト 2」「HTML 1」... と番号付き。内容の無いセクションはファイルが無く数えられないので、タブも出ない。
- 初期選択は最初のテキスト、無ければ最初の HTML、本文が無ければヘッダー（選択はメールごとに保持）。
- ほかに「原文をダウンロード」（`GET .../messages/{key}/raw`）、種類と判定ルール名（`rule`）、抽出結果（抽出したものが無く、自動通知でもないメールには「このメールは処理対象ではありません。」）、所属グループへのリンク。

## 7. ツール（`/tools`）

- 管理者のみ（2.3）。説明 `page.tools.description`。
- カードは 全アドレス同期（受信 → グループ化 → 分析）、受信のみ、グループ化のみ、分析のみ、索引の再構築、再判定、クリーンアップ（[システム仕様](システム仕様.md) 7.1 の `cleanup` の各段階の削除）の順。各カードに説明（`page.tools.tool.<種別>.description`）を、索引の再構築とクリーンアップには注意書き（`page.tools.tool.<種別>.warning`。クリーンアップは、IMAP サーバーから削除したメールは元に戻せないことと、メールが無くなったグループは分析結果とともに削除されること）も表示する。
- いずれも「対象のメールアドレス」（すべてのメールアドレス / 1 件）を選ぶ。全アドレス同期と受信のみは「受信期間」（既定 / 全期間。既定は受信日数の範囲、全期間は target `*`）、分析のみは「分析の範囲」（分析待ちのみ / すべてのグループ）も選ぶ。
- 「実行」で確認ダイアログ（見出し「<ツール名>を実行しますか？」、対象、全期間なら「受信期間: 全期間」、すべてのメールアドレスならメールアドレスごとにジョブを作成して同時実行数の範囲で並行して実行する旨、注意書き）を出す。投入したジョブはジョブ画面（8 章）で確認する。ジョブの一覧にも「全期間」と表示する。
- 「実行」は、そのジョブが何かをできるときだけ押せる: クリーンアップは常に（メールアドレスが無くてもジョブ履歴と保存した結果を整理する）、全アドレス同期と受信のみはすべてのメールアドレスなら有効なアドレスがあるとき、分析のみはメールアドレスがあり設定 API の `analyze_refusal` が空のとき（理由をツールチップに出す）、ほかはメールアドレスがあるとき。

## 8. ジョブ（`/jobs`）

- 管理者のみ（2.3）。
- 「実行中」: 待機中・実行中のジョブをすべて表示する（古い順）。待機中のジョブは取り消せる。ジョブがある間は 3 秒ごと、無いときは 15 秒ごとに自動更新する。待機中・実行中のジョブには進捗（2.5 の `JobProgressLog`）を表示する。
- 「履歴」: 終わったジョブを終了日時の新しい順に表示し、状態のタブ（すべて / 完了 / エラー / 取消。件数付き。URL の `status`。待機中のジョブは「実行中」に表示する）で切り替え、50 件ずつページングする（一覧の上と下にページャー。URL の `page`）。実行中の一覧からジョブが抜けたら履歴を読み直す。

## 9. 設定

### 9.1 設定メニュー（`/settings`）

- 説明付きのメニュー。管理者のみ（2.3）。タイトルの右に「管理者のみ」のバッジを 1 つ表示し、項目ごとのバッジは付けない。
- プロフィール（9.8）はメニューに載せない。

### 9.2 一般設定（`/settings/general`）

- 上部と下部に「保存」ボタン（変更が無い間と、入力エラーがある間は押せない）。
- 入力欄の幅は値の長さに合わせて 2 段階（`Field.tsx` の `ControlWidth`: `short` = 日数・同時実行数・同期時刻の一覧と追加欄・クリーンアップ時刻、`medium` = プロバイダー・モデル・推論レベル）に絞り、ラベル・補足・エラーは絞らずカードの幅で折り返す。
- カードは次の順。
  1. 同期時刻: 説明は `field.setting.checkTimesHint` と `page.settingsGeneral.serverTimeZone`（「サーバーの時刻（<タイムゾーン>）で実行します。」）。時刻の一覧と削除ボタン、無ければ「同期時刻が未設定のため、自動同期は行われません。」。「時刻を追加」の時刻入力と「追加」ボタン、補足「HH:MM の形式（例: 09:00）」、重複なら「この時刻はすでに追加されています。」。
  2. クリーンアップ: 説明「保持期間を過ぎたデータの削除に関する設定です。」とサーバーのタイムゾーン。「クリーンアップ時刻」`cleanup_time` の時刻入力、「メールの保持日数」`mail_keep_days` の数値入力 1〜3650。
  3. 再確認: 説明「対応済・無視にしたグループを、再確認が必要として一覧に戻す条件です。」。「再確認までの日数」`recheck_days` の補足 `field.setting.recheckDaysHint` の下に、カテゴリ名をラベルにした数値入力 1〜365 を並べる（日数の意味と既定値は [メール判定仕様](メール判定仕様.md) 4.5）。
  4. 送信元と DNS 検証（説明 `page.settingsGeneral.dnsCheckHint`）:
     - 「送信元」の欄（補足 `field.setting.sendingSourceHint`: 送信に使うサーバーをすべて登録すること、登録されていない送信元から送信したメールのバウンスは迷惑メールと判定されることがあること、変更後はツールの「再判定」で既存のメールに反映すること）に、「送信元 IPv4」「送信元 IPv6」「送信元ホスト名」の 3 つの textarea（1 行に 1 つ。プレースホルダーは例の値）。欄ごとに形式を検証し（`utils/addressList.ts` がサーバーと同じ規則を持つ。規則は [システム仕様](システム仕様.md) 9.2 の `PUT /api/v1/settings`）、IPv4 欄に IPv6 を書く、ホスト名欄に IP を書くといった誤りは入力エラー。IPv4 / IPv6 の補足は、宛先のメールサーバーへ直接接続して送信する IP アドレスであること。ホスト名の補足は、全メールアドレス共通の送信サーバーのホスト名であり、メールアドレスごとの SMTP サーバーは各メールアドレスの設定で入力すること。
     - 3 つの下に、登録した全監視アドレスの SMTP サーバー（設定 API の `sending_source_mailbox_hosts`）を読み取り専用の一覧「メールアドレスの設定にある SMTP サーバー」で示し（1 つ以上あるときだけ）、補足「各メールアドレスの設定で変更できます。」を添える。
     - その下に帯を 1 つまで出す。警告の帯は、サーバーが返した `sending_source_mailboxes_without_host` が空でなく、「送信元ホスト名」の欄（入力中の値）が空のとき（`sendingSourceNoHost`。ここにホスト名を入力すると、保存前でも消える）に出し、見出し `page.settingsGeneral.sendingSourceNoHost`（「送信元ホスト名が未設定のメールアドレス（送信元以外から送信されたメールのバウンスを見分けられません）」）、該当するメールアドレスの一覧、`page.settingsGeneral.sendingSourceNoHostAction`（「各メールアドレスの「SMTP サーバー」か、この画面の「送信元ホスト名」を入力してください。」）の順に並べ、「送信元 IPv4」「送信元 IPv6」の欄（入力中の値）もともに空のときだけ `page.settingsGeneral.sendingSourceNoHostNoAddress`（「これらのメールアドレスでは、名前解決の失敗もすべて送信側のメールサーバーの問題として扱います。」）を加える。情報の帯 `page.settingsGeneral.sendingSourceEmpty`（「送信元が未設定のため、送信元以外から送信されたメールのバウンスを見分けられません。」）は、3 つの欄（入力中の値）がすべて空で、どの監視アドレスにも SMTP サーバーが無いときに出すが、警告の帯を出している間は出さない（`showSendingSourceEmpty = sendingSourceEmpty && !sendingSourceNoHost`。警告の帯が同じことを伝えるため）。
     - 区切り線の下に DNS 検証の項目を置く: 「DNS 検証」のスイッチ（`ToggleField`。補足 `field.setting.dnsCheckEnabledHint`: 名前解決の失敗を知らせるバウンスが届いたとき、その名前を引き直して原因を確かめること）、「リゾルバー」の textarea（既定の値が入った状態で表示。補足は 1 行に 1 件、10 件までと、既定が Cloudflare、Google、Quad9 であること）、「OS のリゾルバーだけを使う」のチェックボックス（補足「上のリゾルバーにも、ドメインのネームサーバーにも問い合わせません。」）。
     - DNS 検証のスイッチがオフの間は、リゾルバーの textarea とチェックボックスを無効表示にし、チェックボックスがオンの間はリゾルバーの textarea を無効表示にする（無効表示の欄も値を保持し、保存ではそのまま送る）。検証が有効でリゾルバーが 1 つも使えない設定は、リゾルバーの欄に `validation.dnsCheck.noResolver` を出して保存ボタンを押せなくする（サーバーも同じ規則で 400 を返す。[システム仕様](システム仕様.md) 9.2）。
  5. ジョブの実行: 「同時実行数」`workers` の数値入力 1〜16。補足「同時に実行するジョブの数です。同じ IMAP サーバーのアカウントは順番に処理します。」
  6. AI エージェント（説明「バウンスの原因を分析する外部 CLI の設定です。」）:
     - プロバイダー（選択式。CLI が無いものは名前に「(利用不可)」を添える）と「利用可否」のバッジ（利用可能 / 利用不可 / 不明）。CLI が無ければ警告 `page.settingsGeneral.providerUnavailableHint`。
     - モデル（既定は未指定で、プレースホルダー「未指定（CLI の既定のモデル）」）。入力欄の下に、取得できた場合だけ「指定できるモデルの例（クリックで入力）」としてモデル名をクリックで入力できる候補を表示する（取得できなければ何も表示しない。入力欄は自由入力のテキストで、ドロップダウンの候補リストは付けない）。モデル指定に対応しないプロバイダー（設定 API の `model_option` が空）では入力欄を無効にし、補足「このプロバイダーはモデルの指定に対応していません。」を出す。プロバイダーを切り替えると入力は空になる。
     - 推論レベル（選択式。「未設定（CLI の設定に従う）」と、選択中のモデルが受け付ける値（モデル未指定なら既知の全モデルの値））。推論レベルに対応しないプロバイダー（`reasoning_option` が空）では無効にし、補足「このプロバイダーは推論レベルの指定に対応していません。」を出す。モデルを変えて選択中の値が使えなくなったら入力エラーを出して保存ボタンを押せなくする（値は勝手に消さない。サーバーも同じ組み合わせを拒否する。[システム仕様](システム仕様.md) 6.1）。プロバイダーを切り替えると未設定に戻る。
     - 「自動分析を有効にする」のスイッチ（`ToggleField`。一般的なサイズ）、「作業ディレクトリの保持日数」`agent_keep_days` の数値入力 1〜365。
  7. サーバー情報: 説明「起動オプションで指定する値のため、ここでは変更できません。」。待ち受けアドレス、待ち受けポート、データディレクトリ。

### 9.3 通知（`/settings/notifications`）

- 説明「対応が必要なアラートの一覧を、通知先の利用者にメールで送信します。」。送る内容と送信の条件は [システム仕様](システム仕様.md) 7.4。
- SMTP 設定（説明「通知メールの送信に使うメールサーバーです。」）: SMTP ホスト、ポート、接続方式、ユーザー名、パスワード、差出人アドレス。
  - 接続方式「暗号化なし」（`none`）は平文のため注意書きを表示する。
  - ユーザー名は認証が不要なら空欄。空にして保存すると保存済みパスワードも消す。
  - パスワードはユーザー名が空の間は入力できない。設定済みなら「設定済み」と表示し、空で据え置き。ユーザー名を設定するのにパスワードが入力も保存も無ければ `validation.connection.passwordRequired`、パスワード保存中に接続設定を変えるのにパスワードが無ければ `validation.connection.passwordRequiredOnChange` を出して保存できない。
- テスト送信（SMTP 設定の下。補足「入力中の SMTP 設定で、テストメールを送信します。」）: 送信先（空欄なら操作した利用者のメールアドレス）と「テスト送信」ボタン。入力中の値（ホスト・ポート・接続方式・ユーザー名・入力したパスワード・差出人）をすべて `POST /api/v1/notifications/test` に送るので、保存前でも押せる。押せるのは、ホストと差出人アドレスが空でなく正しく、ポートが正しく、送信先（入力した宛先、または操作した利用者のメールアドレス）があり、パスワードが要らないとき（ユーザー名が空、または保存済みパスワードがあって接続設定が保存値のまま、またはパスワードを入力した）。
- 通知設定: 「通知を有効にする」のスイッチ、通知時刻（補足にサーバーのタイムゾーン）、通知間隔 1〜7 日の選択（毎日 / 2 日ごと / ... / 7 日ごと）、通知先の利用者のチェックリスト（メールアドレス未登録の利用者は選べるが「メールアドレス未登録」と表示し、送信対象の人数と未登録の人数を示す）、公開 URL（補足と「使用する URL:」）、最終送信・次回送信の表示。
  - 「今すぐ送信」（補足「通知時刻を待たずに、保存済みの設定で通知メールを送信します。」）: 保存済みの SMTP ホストと差出人アドレス、メールアドレスのある通知先がそろわないときは押せない。
  - 通知を有効にしたまま SMTP ホストか差出人アドレスが空なら、その欄に `validation.notification.smtpRequired` を出して保存できない。

### 9.4 確認メール（`/settings/probe`）

- 管理者のみ。説明 `page.probeSettings.description`。上部と下部に「保存」ボタン。設定値の規則は [システム仕様](システム仕様.md) 7.6。
- 確認メールサーバー（IMAP）のカード（説明 `page.probeSettings.serverHint`: 到着を確認した確認メールだけを削除するため削除の権限が要ること）: 確認メールの宛先、ホスト名、接続方式、ポート、ユーザー名、パスワード（設定済み表示、空で据え置き。接続を変えるときは再入力が必要）、フォルダー、識別子（補足 `field.probe.subjectTagHint`）、「接続テスト」（入力中の値で試す）。
- 送信と判断時間のカード: 「確認メールを有効にする」のスイッチ（宛先と確認メールサーバーが揃うまで保存できない）、送信時刻（追加・削除。サーバーのタイムゾーンを表示）、遅延判断時間と障害判断時間（分。1〜10080、障害判断時間は遅延判断時間より長い）、確認メールを送るメールアドレスの数とメールアドレスの設定へのリンク、遅延と障害は通知メールの有効・無効にかかわらず「通知」の SMTP サーバーから通知先に送る旨。

### 9.5 メールアドレス（`/settings/mailboxes`、`/settings/mailboxes/new`、`/settings/mailboxes/:id`）

- 一覧（説明 `page.settings.menu.mailboxes`）: ドメイン → アドレスの順で、メールアドレス・サーバー・受信日数（`recent_days`）・保持日数（`server_keep_days`。0 は「削除しない」）・状態・最終同期の列と、操作（編集・削除）を表示する。
- 削除の確認ダイアログには「原文ファイルを残す」のチェックボックス（`?keep_data=1`）を置く。
- 追加・編集画面のカードは次の順。
  1. 基本情報: メールアドレス（補足「英字は小文字に変換して保存します。」）、表示名、「監視を有効にする」のスイッチ。
  2. IMAP 接続（説明「受信サーバーへの接続情報です。パスワードは暗号化して保存します。」）: ホスト名、接続方式、ポート、ユーザー名、パスワード、フォルダー、「接続テスト」。接続方式「暗号化なし」を選ぶと警告 `field.connection.securityNoneWarning` を表示する。編集でホスト名・ポート・接続方式・ユーザー名を変えるときはパスワードの再入力が必要（空のままなら送信前に `validation.connection.passwordRequiredOnChange`。サーバーの規則と接続テストでのパスワードの扱いは [システム仕様](システム仕様.md) 9.2）。
  3. 送信サーバー:
     - 先頭に「送信確認をする」のスイッチ（既定オフ。補足 `field.mailbox.probeEnabledHint`）。
     - その下に「SMTP サーバー」の欄（任意。プレースホルダー `mail.example.jp`。補足なし）。ホスト名の規則は一般設定の「送信元ホスト名」と同じで、画面でも検証する（`validation.mailbox.smtpHostInvalid`）。判定での使われ方（送信元としての照合と、このアドレスで送信元以外から送信されたメールのバウンスの判定を有効にすること）は [メール判定仕様](メール判定仕様.md) 2.6・2.7・4.4。変えても IMAP のパスワードの再入力は要らず、接続テストには含めない。
     - この欄が空で、保存済みの一般設定の `sending_source_hosts` も空のときは、欄の下に警告 `page.mailboxes.smtpHostMissing`（「未設定のため、このメールアドレスでは送信元以外から送信されたメールのバウンスを見分けられません。」）を出す。
     - 送信確認をオンにすると、「SMTP サーバー」と同じ行に接続方式（既定 `starttls`）・ポート（必須。空欄から入力し、例として 587 を表示）、次の行にユーザー名（任意。認証が不要なサーバーでは空欄）・パスワード（ユーザー名があるときだけ入力できる。設定済み表示、空で据え置き。ユーザー名があって保存済みのパスワードも入力も無ければ入力エラー）と「テスト送信」（確認メールの宛先へテストメールを送る。宛先が未設定なら押せず `page.mailboxes.probeNoAddress` を表示）が現れ、このサーバーから確認メールを送る（[システム仕様](システム仕様.md) 7.6）。
     - オンでホスト名かポートが無ければ入力エラー。オフのときはホスト名だけを保存する。送信確認がオンでパスワード保存中に、ホスト名・ポート・接続方式・ユーザー名を変えるときはパスワードの再入力が必要（IMAP と同じ規則）。メールアドレスが無効なら `page.mailboxes.probeDisabledNote` を添える。
  4. 受信期間（説明 `page.mailboxes.sectionRangeHint`）: 「初回の受信日数」（既定 90）と「通常の受信日数」（既定 10）。
  5. サーバー上のメールの削除（説明 `page.mailboxes.sectionServerKeepHint`）: 「サーバーでの保持日数」`server_keep_days` の数値入力 0〜3650。補足に「メールの保持日数（N 日）以下で入力します。」を添え、超えると `validation.mailbox.serverKeepDaysOverMailKeep`（保存済みの値のままなら可）。0 の意味、新規の初期値、削除の規則は [システム仕様](システム仕様.md) 5.6.1。

### 9.6 利用者（`/settings/users`）

- 一覧はユーザー名・表示名・役割・メールアドレス・最終ログイン・作成日時を別々の列で表示し、ログイン中の利用者の行にはバッジ `page.users.currentUser` を付ける。言語・タイムゾーン・テーマは一覧に出さず、作成・編集フォームだけに置く。
- 表示名を空にして保存するとユーザー名になる（作成時と同じ）。

### 9.7 トークン（`/settings/tokens`）

- 管理者のみ。将来の API 用の予約機能で、利用者とは無関係。
- 発行時に値を一度だけ表示する。有効期限は 7 / 30 / 90 / 365 日のプリセットまたは日時指定を RFC 3339 で送る。デフォルトのトークンにはバッジを表示する。

### 9.8 プロフィール（`/settings/profile`）

- 全利用者。設定メニューには載せず、右上の利用者名のメニューから開く（`/settings/account` は `/settings/profile` へ転送）。
- 表示名（空にして保存するとユーザー名になる）、通知用メールアドレス、言語（`ja` / `en`）、タイムゾーン（IANA 名の一覧から選択）、テーマ（自動 / ライト / ダーク）の変更（保存で即時反映）と、パスワードの変更。
