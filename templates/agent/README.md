# templates/agent

Files under `templates/agent/<provider>/` are copied into the agent workspace
of the run (`data/agent/<address>/<group_key>/<report_id>/`, one directory
per analysis run, removed after `agent_keep_days`) right before the provider
CLI runs there. They are the workspace skeleton: operating rules the CLI picks up on
its own (for codex that is `AGENTS.md`), and nothing else. While the CLI runs
the workspace holds only these files and the evidence files
(`evidence/<message_key>.txt`, written by `app/modules/agent/evidence.go`);
the prompt itself is generated by `app/modules/agent/prompt.go`, fed to the
CLI and written to `PROMPT.md` after the CLI has ended.

The directory is embedded into the binary from `embed.go` and handed to the
agent package as `AnalyzeInput.TemplatesFS`. A provider without a directory
here simply runs in an empty workspace.

## Layout

```text
templates/agent/
  README.md                this file (not copied)
  report_headings_ja.txt   the four Japanese report headings of the prompt, one per line (not copied)
  codex/
    AGENTS.md              rules codex reads automatically from its cwd
```

`report_headings_ja.txt` is read by `prompt.go` (`ReportHeadingsFileJa`) so
that the Go sources stay ASCII-only: the lines are the level-2 headings the
agent must use, in the order cause, impact, actions, responsible. When the
file is missing or has fewer than four lines the English headings are used.

Every file and sub-directory below `templates/agent/<provider>/` is copied
verbatim (files 0600, directories 0700). Existing files in the workspace are
overwritten on every run, so keep the templates self-contained.

## Adding a provider

Adding an agent CLI touches exactly one Go file plus, optionally, one
template directory. Nothing else branches on a provider name.

1. Create `app/modules/agent/provider_<name>.go`:

   ```go
   package agent

   func init() { registerProvider(exampleProvider{}) }

   type exampleProvider struct{}

   func (exampleProvider) Name() string  { return "example" } // stored in settings / reports
   func (exampleProvider) Label() string { return "Example" } // shown in the UI

   // Non-interactive, read-only launch argv. Placeholders:
   //   {prompt}       the prompt text as one argv element
   //   {prompt_file}  the path of PROMPT.md in the workspace
   //   {cwd}          the workspace directory
   // Without {prompt} / {prompt_file} the prompt is fed on stdin.
   func (exampleProvider) Command() []string {
       return []string{"example", "--non-interactive", "--read-only", "--prompt-file", "{prompt_file}"}
   }
   ```

   Requirements for `Command()`:
   - It must run without a TTY and exit on its own when the answer is done.
   - It must be locked down: no file writes outside the workspace, no
     commands that change state, no network. Prefer the CLI's own sandbox
     flags (codex: `--sandbox read-only`).
   - It must be able to read files inside the workspace (the evidence files
     under `evidence/`). The agent is never pointed at the mail files under
     `data/mails/`.
   - The exit code is ignored; success is decided by the `<<<MLC:REPORT>>>`
     block in the combined stdout+stderr. The command is executed directly
     (no shell), so it works the same on Windows, macOS and Linux;
     `exec.LookPath` decides availability from `Command()[0]`.

   Optional extensions (implement only what the CLI supports; without one
   the matching feature is simply off for the provider):

   - `ModelSelector` (`app/modules/agent/model.go`) when the CLI accepts a
     model: `ModelOption()` names the option shown in the settings
     (`--model`), `ModelArgs(model)` returns the arguments that select it
     (appended to `Command()`) and `Models()` lists model names for
     reference (nil when unknown; it must be cheap and never fail). Without
     it the `agent_model` setting is ignored and the settings disable the
     input.
   - `ReasoningSelector` (`app/modules/agent/reasoning.go`) when the CLI
     accepts a reasoning level: `ReasoningOption()` names the option shown in
     the settings, `ReasoningArgs(level)` returns the arguments that set it
     (appended after the model arguments) and `ReasoningLevels()` maps each
     known model to the levels it accepts (nil when unknown; cheap, never
     fails). Saving a level is checked against that map. Without it the
     `agent_reasoning_effort` setting cannot be set for the provider.
   - `UsageReporter` (`app/modules/agent/usage.go`) when the CLI output tells
     the model, the reasoning level, the tokens used or the commands the
     agent ran: `ParseUsage(raw, answer)` reads them (raw = full transcript,
     answer = transcript after the echoed prompt); whatever it cannot read
     stays empty / NULL on the report.
   - `RateLimitDetector` (`app/modules/agent/ratelimit.go`) when the CLI
     reports usage limits in its own way.

2. Optionally add `templates/agent/<name>/` with the files the CLI reads from
   its working directory (for example `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`).
   Copy `codex/AGENTS.md` as a starting point: it states the read-only rules,
   that only the evidence files named by the prompt may be read (and only
   under its conditions), and the prompt-injection stance.

3. Register nothing else. The provider appears automatically in
   `agent.Providers()` (name order), in the settings screen and in
   `settings set agent_provider <name>` validation.

4. Add a test in `app/modules/agent/` only if the provider needs special
   handling; the shared pipeline (workspace, prompt, parsing, storage) is
   already covered by `run_test.go` through a fake provider.

Examples of commands for other CLIs (verify the flags against the installed
version before enabling them):

| CLI | Command | Notes |
| --- | --- | --- |
| codex | `codex exec --sandbox read-only --skip-git-repo-check` | prompt on stdin; the current provider (model: `--model <m>`, reasoning level: `-c model_reasoning_effort="<level>"`) |
| claude | `claude -p --allowedTools Read` | prompt on stdin; only the Read tool is pre-approved, so every other tool is denied |
| gemini | `gemini -p {prompt} --sandbox` | prompt inline; check that the sandbox allows reading the evidence files in the workspace |

## Prompt and output contract

The prompt structure, the two marker blocks (`<<<MLC:REPORT>>>` and
`<<<MLC:META>>>`) and the parsing rules are documented in
`Documents/プロンプト仕様/バウンス分析 プロンプト仕様.md`. They are provider
independent; templates must not redefine them.
